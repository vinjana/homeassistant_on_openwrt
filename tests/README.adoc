= Testing the Home Assistant OpenWrt Migration
:toc:
:toclevels: 2
:sectnums:
:source-highlighter: rouge

== Overview

This directory contains scripts for testing the `ha_install.sh` migration to OpenWrt 25.12.3.
The goal is *operational qualification*, not functional testing of Home Assistant itself:
we verify that the install script completes, that all Python native libraries load correctly,
and that Home Assistant starts and answers on port 8123.

`vm-test.sh` is the primary entry point for end-to-end test runs.
The individual `vm-*.sh` scripts remain available for single-step use.
All scripts share a common library, `vm-lib.sh`, which provides arch configuration
(`arch_config`), SSH helpers (`init_ssh`, `ssh_run`, `wait_for_ssh`), PID file
management (`pid_write`, `pid_running`, `pid_kill`), and pristine image snapshotting
(`save_pristine`, `restore_pristine`).

Testing is staged from cheapest to closest-to-reality:

[cols="1,2,2",options="header"]
|===
|Stage |Environment |What it catches
|1 |x86_64 QEMU VM (KVM) |Package manager, Python 3.13 compat, pure-Python deps, fast iteration
|2 |aarch64 QEMU VM (TCG emulation) |Binary wheel availability for `aarch64-musllinux`, arch-specific feed packages
|3 |OpenWrt One (physical) |Final real-hardware qualification
|===

== Prerequisites

=== Host packages (Ubuntu)

.Stage 1 only — x86_64 QEMU (KVM)
[source,bash]
----
sudo apt-get install \
    qemu-system-x86 \   # qemu-system-x86_64 binary
    qemu-utils \        # qemu-img (image resize)
    parted \            # partition table manipulation (no root needed on image files)
    gdisk \             # sgdisk (relocate GPT backup header after image resize)
    e2fsprogs \         # e2fsck, resize2fs, dumpe2fs, debugfs
    openssh-client \    # ssh, scp
    wget                # image download
----

.Stage 2 additionally — aarch64 QEMU (TCG software emulation)
[source,bash]
----
sudo apt-get install \
    qemu-system-arm \   # qemu-system-aarch64 binary
    qemu-efi-aarch64    # UEFI firmware (QEMU_EFI.fd) required to boot the armsr/armv8 image
----

NOTE: `python3` (used by `qemu-img info` output parsing in `vm-setup.sh`) is assumed to be already present on any modern LINUX system.

=== KVM access (required for Stage 1 acceleration)

x86_64 runs with KVM hardware virtualisation, which requires your user to be in the `kvm` group:

[source,bash]
----
ls -la /dev/kvm                     # verify KVM device is present
sudo usermod -aG kvm $USER          # add yourself to the kvm group
# log out and back in (or: newgrp kvm in the current shell)
----

aarch64 uses TCG software emulation and does not require KVM.

== Stage 1: x86_64 QEMU VM

=== One-time setup

[source,bash]
----
cd tests/
./vm-setup.sh
----

This script requires no `sudo`. All operations work on regular files in userspace:

. Downloads the OpenWrt 25.12.3 x86_64 combined ext4 image (skips if already present).
. Extends the image file to 2 GB with `qemu-img resize`; relocates the GPT backup header with `sgdisk`.
. Expands partition 2 using `parted` on the image file (no block device needed).
. Extracts the partition to a temp file, expands the ext4 filesystem with `resize2fs`, and writes it back with `dd` (no loop device or root needed).
. Injects a `uci-defaults` script via `debugfs` that configures a second NIC (eth1) for DHCP
  so that QEMU's user-mode networking can reach the VM via the SSH port-forward.
. Saves a pristine snapshot (`*.pristine.img`) of the fully-configured base image.
  Subsequent test runs restore from this snapshot instead of re-downloading.

The script is idempotent — safe to re-run.

=== End-to-end test run

[source,bash]
----
./vm-test.sh           # restore from pristine → start → install → qualify → stop
----

If any step fails the VM is stopped automatically.
To run a specific step only:

[source,bash]
----
./vm-test.sh --step setup    # restore working image from pristine snapshot (fast)
./vm-test.sh --step start    # start VM and wait for SSH
./vm-test.sh --step run      # pipe ha_install.sh to the VM
./vm-test.sh --step qualify  # run qualification checks
./vm-test.sh --step stop     # stop VM
./vm-test.sh --step all      # same as no --step: full run
----

To use a different install script:
[source,bash]
----
./vm-test.sh x86_64 /path/to/modified_ha_install.sh
----

=== Running the VM

[source,bash]
----
./vm-start.sh          # boots VM, waits for SSH on port 2222
./vm-stop.sh           # shuts down the VM
----

Connect manually:
[source,bash]
----
ssh -o StrictHostKeyChecking=no root@localhost -p 2222
----

=== Installing Home Assistant

[source,bash]
----
./vm-run.sh            # runs ../ha_install.sh on the VM via SSH pipe
# or supply a different script:
./vm-run.sh /path/to/modified_ha_install.sh
----

The script streams output directly to your terminal.
On failure, fix `ha_install.sh`, stop and restart the VM (to get a clean state), then re-run.

=== Resetting to a clean state

Restore the working image from the pristine snapshot (instant on CoW filesystems):

[source,bash]
----
./vm-test.sh --step setup
----

If you need to recreate the pristine snapshot itself (e.g. after changing the base image
configuration), delete both images and re-run setup:

[source,bash]
----
./vm-stop.sh
rm tests/openwrt-25.12.3-x86-64-generic-ext4-combined.img
rm tests/openwrt-25.12.3-x86-64-generic-ext4-combined.pristine.img
./vm-setup.sh          # re-downloads, re-patches, and saves a new pristine snapshot
----

=== Operational qualification

[source,bash]
----
./vm-qualify.sh
----

Checks performed:

* Native library imports: `ciso8601`, `cryptography`, `PIL`, `bcrypt`, `aiohttp`, `uv`, `yaml`, `sqlalchemy`, `zeroconf`
* Home Assistant package import and version string
* HA service starts via `/etc/init.d/homeassistant start`
* Port 8123 responds with a valid API response (up to 30 s wait)
* hass-configurator answers on port 3218
* HA init script is enabled (persists across reboot)

Exit code 0 = all checks pass.

== Stage 2: aarch64 QEMU VM

Once Stage 1 is clean, repeat on the aarch64 target to catch architecture-specific issues
(binary wheel availability for `aarch64-musllinux`, etc.).

All scripts accept an `[arch]` argument; pass `aarch64` throughout.
The aarch64 VM uses host port **2223** (so both VMs can run simultaneously if needed).

=== One-time setup

[source,bash]
----
sudo apt-get install qemu-system-arm qemu-efi-aarch64
cd tests/
./vm-setup.sh aarch64
----

=== End-to-end test run

[source,bash]
----
./vm-test.sh aarch64
----

aarch64 uses TCG software emulation (no KVM), so boot and install are significantly slower
than Stage 1. Allow 10–20 minutes for `ha_install.sh` to complete.

The `--step` flag works the same as for x86_64.

=== Resetting to a clean state

[source,bash]
----
./vm-test.sh --step setup aarch64
----

To recreate the pristine snapshot:

[source,bash]
----
./vm-stop.sh aarch64
rm tests/openwrt-25.12.3-armsr-armv8-generic-ext4-combined-efi.img
rm tests/openwrt-25.12.3-armsr-armv8-generic-ext4-combined-efi.pristine.img
./vm-setup.sh aarch64
----

== Stage 3: OpenWrt One (physical hardware)

The OpenWrt One already runs OpenWrt 25.12.3 (r32912-6639b15f62) — no firmware flash needed.

[source,bash]
----
ssh root@<router-ip> 'sh -s' < ../ha_install.sh
----

NOTE: OpenWrt only provides `ash`; `bash` is not available on the device.
Use `sh -s` (POSIX sh, satisfied by ash), not `bash -s`.

== Iteration workflow

The recommended workflow for fixing issues in `ha_install.sh`:

[source,bash]
----
# 1. edit ha_install.sh on the host
# 2. run the full test cycle (restores pristine, installs, qualifies, stops)
./vm-test.sh x86_64
# 3. repeat from 1 until all checks pass
# 4. repeat on aarch64
./vm-test.sh aarch64
----

To inspect the VM mid-run, use single-step mode:

[source,bash]
----
./vm-test.sh --step setup x86_64   # restore pristine
./vm-test.sh --step start x86_64   # start VM
# ... connect manually, inspect, iterate ...
ssh -o StrictHostKeyChecking=no root@localhost -p 2222
./vm-test.sh --step run x86_64     # run install
./vm-test.sh --step qualify x86_64 # qualify
./vm-test.sh --step stop x86_64    # stop
----
